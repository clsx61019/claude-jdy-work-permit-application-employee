- **模板：** 都由 `tools/build_employee_documents.py` 从简道云原模板转换而来。双语的统一为左栏匈牙利语、右栏英语（见 `tools/bilingual.py`）。

|---|---|---|---|
| Accommodation Certificate | accommodation_certificate.docx | 住宿证明 Szállásigazolás | Polimer（住处经营单位） |

| Declarations 第 1 页 | request_previous_documents.docx | 沿用材料请求 Kérelem | 员工 |
| Declarations 第 2 页 | request_delivery_address.docx | 通信和寄卡地址请求 Kérelem | 员工 |

- **实现：** `service/forms/` 下同名模块，员工信息的通用写法在 `employee_common.py`；测试样例 `tests/samples/employee_documents.json`（延期、ICT、已开始工作）、`employee_documents_new.json`（新申请、匈牙利卡、承包商、还没开始工作）

## 什么时候能生成

| 模板 | 条件（不满足就报错） |
|---|---|
| 住宿证明 | 「匈牙利居住地」是 Polimer 经营的住处：Hotel BorsodChem、Hotel Fremon、Relax Center（B2） |
| 雇主用工情况报告 | 雇主在 `config/employers.json` 里有地址、税号、公司注册号、雇主代表（雇主代表待办 J13） |

| 通信和寄卡地址请求 | 所有申请（B7） |
| 员工同意雇主代为递交 | 递交地点 = 匈牙利（B8） |

## B. 内容（2026-10-31 确认）

| # | 问题 | 结论 |
|---|---|---|
| B1 | 文件名 | 按上表；Declarations 拆成三份 |
| B2 | 住宿证明给哪些住处用 | Hotel BorsodChem、Hotel Fremon、Relax Center 都是自己的酒店，归 Polimer Szolgáltató Kft.。写在 `config/accommodation.json` 的 operator 里，其他住处报错 |
| B3 | 住宿证明不写住多久 | 不加 |
| B4 | 雇主通知 a/b/c 和卡号 | 卡号取「居留卡号」。有「劳动关系实际起始日期」时填 a) 的日期，删掉 b)、c)，这时卡号必须有；没有时三行都留着手填 |
| B5 | 雇主通知落款日期 | 生成当天（2026. október 31. 这种写法） |
| B6 | 雇主通知签字人 | 印雇主代表（`employers.json` 的 representative_hu，待办 J13），下面一行「(cégszerű aláírás)」 |
| B7 | 员工声明什么时候打印 | 沿用材料请求、住址未变声明只给延期；通信和寄卡地址请求给所有申请 |
| B8 | 员工同意书写死 ICT | 按「居留许可类型」，匈语用 9 号申请表第 9 部分的写法；只在递交地点 = 匈牙利时生成 |
| B9 | 员工签的几份签字地点写死 Kazincbarcika | 按「递交地点」：中国 Beijing / Peking，匈牙利 Kazincbarcika（和 IMO 授权书一样）。住宿证明由 Polimer 签，仍是 Kazincbarcika |

## 需要和操作人员核对

- 雇主通知现在是交纸质，还是在 Enter Hungary 线上报？如果只在线上报，这份模板可以不用（C1，待确认）
- 雇主通知的 b)、c) 用得不多（C2），所以没有加字段，需要时手填
- 住址未变声明：简道云没有「住址是否变了」的字段（C3），住址变了的话由操作人员决定不打印
- 员工同意书：雇主在匈牙利递交时，员工多半还在中国签字，但按 B9 签字地点会印 Kazincbarcika。如果实际在中国签，需要另定规则
- 各份签字日期都用「劳动合同预协议&居留许可申请表签字日期」，延期时是否也是同一天签
