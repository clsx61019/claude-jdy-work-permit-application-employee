# 项目计划

## 原则

- **先打印，后表单。** 辅助字段只能在没有任何模板用它之后才能删，所以打印迁移是表单瘦身的前提。
- **不在会被删掉的东西上投入。** 现有公式不再优化，只修会导致文件出错的问题。
- **两套并存过渡。** 新打印服务上线一个模板，就对比一个模板；简道云原模板保留到对应的新模板验收完。
- **规则逐条确认。** 每个模板一张规则清单，我先起草，负责人审核。

## 阶段 0：准备和止血

不依赖新方案，可以马上做。

- [ ] 建私有 GitHub 仓库，推送本项目
- [ ] 流程状态：触发条件改为「节点流转」，去掉「状态确认」和 11 个节点校验（或者直接改用系统字段「当前节点」）
- [ ] 修正会导致文件出错的写死规则：二次入职前任雇主、工作地点里的万华判断
- [ ] 删除测试残留的打印模板

- [ ] 待确认：非万华员工跳过节点 8 是否有意

## 阶段 4：流程重构

- [ ] 开启退回到「0. 信息提交」
- [ ] 处理人改为角色，加超时提醒
- [ ] 合并只有确认动作的节点（8、10）
- [ ] 主数据自动写回，替代「手动导入数据库」按钮；年龄改为动态计算
  - 「1. 信息确认」后建档（状态 Pending），用姓名 + 出生日期查重（比较前去空格、统一大写；查到多条时不自动写，提醒人工处理）
  - 申请表加关联字段指向档案记录，之后所有更新按关联
  - 流程结束后写入居留卡号、有效期、医保卡号、税号，状态改为 Active
  - 按「人员类别」写入外派人员 / 承包商 / 家属数据库；家属关联到对应员工
  - 已有就更新、没有才新建，可重复执行
- [ ] 邮件收件人改为从「通知人员邮箱汇总」读取
- [ ] 汇率改为官方来源或「历史汇率」辅助表
