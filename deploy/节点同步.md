# 节点同步函数（jdy-node-sync）

把流程的当前节点、当前负责人、进入时间、停留天数写进表单普通字段，供仪表盘按节点统计。
简道云仪表盘用不了系统字段「当前节点」「当前负责人」，所以需要这一步。

## 怎么工作

- 数据来源：官方接口「查询流程实例信息」，取状态为进行中的待办。读的是真实待办，回退、撤回、转交、手动结束都会自动改对。
- 即时：简道云「数据推送 → 流程变更时推送」，勾「流程待办变更时」「流程状态变更时」，推到本函数的函数 URL。
- 兜底：定时触发器，默认每小时把所有需要同步的记录对一遍（流程进行中的，以及字段还停在某个节点但流程已结束的）。
- 只在值变了才写回，不会循环；停留天数每天变一次。
- 「当前节点」先英后中：编号补零 + 英文名 + 中文名，如「01A HR Confirmation HR确认」，对照表在 `sync/node_sync.py` 的 NODE_NAMES（按编号对应，流程里节点名怎么改都不影响）。没有对照的节点按原名写。
- 流程进行中但没有进行中的待办时，写「Waiting for Notification Subflow 等待通知子流程」（第一轮、第二轮通知都是子流程）。流程结束写「Completed 已完成」，手动结束写「Terminated 已手动结束」。
- 「当前节点」下拉框的选项就是 NODE_NAMES 拼出来的 14 个，加上面 3 个固定值，必须一字不差。

## 表单字段（测试表，所有节点可见、不可编辑）

| 字段 | 类型 | GitHub Variable |
| --- | --- | --- |
| 当前节点 | 单行文本 | FIELD_NODE |
| 当前负责人 | 成员多选 | FIELD_ASSIGNEE |
| 进入当前节点时间 | 日期时间 | FIELD_ENTERED |
| 当前节点停留天数 | 数字 | FIELD_DAYS |
| 节点同步时间 | 日期时间（节点信息最后一次变化的时间） | FIELD_SYNCED |
| 递交日期（读） | 日期 | FIELD_SUBMITTED |
| 获批日期（读） | 日期 | FIELD_APPROVED |
| 递交至今天数 | 数字：今天 − 递交日期；有获批日期后固定为获批日期 − 递交日期 | FIELD_SINCE_SUBMIT |
| 办理总天数 | 数字：获批日期 − 发起日期；没获批时为空 | FIELD_TOTAL |

天数按布达佩斯日期算。后四个都配置了才算天数；天数变化不更新「节点同步时间」。流程结束后不再刷新天数（结束前已按获批日期固定）。

## 部署

1. Actions →「部署节点同步」→ Run workflow（这时还不需要 `SYNC_PUSH_SECRET`）。接口建函数失败时，按日志提示在控制台法兰克福手动建一个空的 Python 3.10 事件函数 `jdy-node-sync`，再跑一次。
2. 日志里会打印推送地址（函数 URL），填到简道云数据推送的「服务器地址」，勾「流程待办变更时」「流程状态变更时」，点「服务器连接测试」。没配置密钥时函数先不校验签名，所以测试能通过。
3. 在简道云点「生成 Secret」，把同一个值存为 GitHub Secret `SYNC_PUSH_SECRET`，再跑一次 Run workflow。之后签名不对的推送会被拒绝（403）。
4. 日志最后会试跑一次全量同步，看 `checked`、`changed`、`errors`。

## 上线后

- 新旧两套并行一段时间，对比「当前节点」和真实待办；对得上再停用旧的「流程状态修改」智能助手，删除两个「当前流程状态」字段。
- 第一次收到推送时，函数日志会打印推送内容，用来核对流程推送的字段格式。
